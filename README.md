# НИЛ «МЛСИ»: планировщик социологической лаборатории

Веб-приложение на Python 3.10+. Данные и вложения хранятся в SQLite (`data/lab.db`).

## Запуск

```sh
python -m pip install -r requirements.txt
python server.py
```

Откройте `http://127.0.0.1:8000`. При первом входе создайте учётную запись администратора. После этого администратор добавляет исследователей и интервьюеров в разделе «Команда». Не открывайте `index.html` напрямую: приложению необходим запущенный сервер.

После создания первого администратора в карточках автоматически появится одно исследование «ДЕМО · Warhammer 40,000: интерес к настольному хобби» с анкетой из 10 вопросов и **385 вымышленными ответами**. В существующей базе оно добавится при следующем запуске сервера. Повторные запуски не добавляют копии и не сбрасывают изменения в исследовании; учебная карточка защищена от удаления через интерфейс. Данные синтетические и предназначены только для проверки функций и новых версий приложения, а не для выводов о реальных людях. Для запуска без автоматического добавления в новую базу задайте `LAB_DEMO_STUDY=0` (ранее добавленная карточка останется в базе). Демо-ответы в отчёте учитываются как импортированные анкеты.

Для доступа с других устройств в одной сети на Windows PowerShell:

```powershell
$env:HOST = "0.0.0.0"
python server.py
```

Откройте IP-адрес компьютера с портом `8000` для работы в одной сети. Для работы с телефона **из любой сети** разместите сервер за HTTPS-прокси с доступным доменным именем (или через защищённый туннель/VPN), установите `COOKIE_SECURE=1` и откройте на телефоне HTTPS-адрес. Просто указать `HOST=0.0.0.0` недостаточно для доступа из интернета. Не публикуйте встроенный HTTP-сервер напрямую. После изменения серверного кода перезапустите `python server.py`. Выполняйте резервное копирование файла базы данных `data/lab.db`.

## Развёртывание на Render

Для корневого приложения выберите в Render репозиторий `anikimon/MLSI`, ветку `main`, корневой каталог репозитория, команду сборки `pip install -r requirements.txt` и команду запуска `python server.py`. На Render сервер слушает `0.0.0.0` и порт из переменной `PORT`; при необходимости можно явно задать `HOST=0.0.0.0`. Для входа по HTTPS задайте `COOKIE_SECURE=1`. Если данные уже есть, сохраните прежний путь `LAB_DB` на постоянном диске: смена пути создаст новую пустую базу. После отправки коммитов проверьте в Render выбранную ветку, включён ли Auto-Deploy и какой коммит указан у последнего деплоя; при отключённом Auto-Deploy запустите развёртывание вручную.

## Развёртывание на Amvera и перенос с Render

В корне репозитория есть `amvera.yaml`: Amvera собирает Python-приложение из `requirements.txt`, запускает `server.py` на порту 8000 и монтирует постоянное хранилище в `/data`. При запуске в Amvera сервер по умолчанию слушает `0.0.0.0:8000`, сохраняет SQLite в `/data/lab.db` и устанавливает `Secure` для cookie. Локальный запуск и переменные `HOST`, `PORT`, `LAB_DB`, `COOKIE_SECURE` сохраняют прежнее поведение; не указывайте `LAB_DB` внутри `/app` или относительным путём при развёртывании.

1. Создайте приложение типа Python в Amvera и загрузите этот репозиторий в Code (либо подключите GitHub и нужную ветку). Убедитесь, что `amvera.yaml` попал в Code; запустите сборку. Первый запуск создаст пустую `/data/lab.db`. Установите **одну реплику**: приложение использует SQLite и хранит состояние ограничителей запросов в памяти процесса.
2. Если нужны существующие пользователи, ответы и вложения, перенесите **актуальную базу с Render**: всё это хранится в одном файле SQLite. Найдите на Render путь из `LAB_DB` (если переменная не задана — `data/lab.db` относительно приложения). Прекратите запись новых ответов, остановите приложение Render и скачайте файл БД из его постоянного диска; если копируете базу при работающем сервере, сначала сделайте согласованный снимок через SQLite Backup API, а не копируйте открытый файл вручную. Не используйте локальную `data/lab.db`, если она не содержит последних данных Render.
3. После первого успешного запуска Amvera остановите приложение, откройте «Репозиторий» → **Data** и загрузите файл как `lab.db` в корень Data (заменив созданную пустую базу). **Не загружайте БД в Code** и не добавляйте её в Git. Запустите приложение снова, проверьте вход, проекты, ответы и вложения, и только после этого переключайте пользователей со старого адреса. До переключения храните копию исходной БД; дальнейшие записи на Render после снимка не попадут в Amvera.
4. Если используете DeepSeek, задайте `DEEPSEEK_API_KEY` в разделе «Переменные» Amvera как **секрет**; `key.txt` не загружается из Git. После изменения секрета перезапустите контейнер. Аналитический PDF автоматически использует системный TTF-шрифт с кириллицей; для Times New Roman или другого разрешённого шрифта загрузите TTF в Data и задайте `PDF_TIMES_FONT=/data/имя_файла.ttf`. Для долгосрочного хранения локальной модели распознавания можно загрузить её в Data и задать `ASR_MODEL=/data/путь_к_модели`. Учитывайте память и место на диске для `faster-whisper`.

Проверяйте состояние приложения в «Лог приложения» и наличие `lab.db` в «Репозиторий» → Data. Настройте резервное копирование Data; HTTPS-адрес Amvera нужен для входа с телефона и офлайн-PWA. [Документация Amvera: Python](https://docs.amvera.ru/applications/environments/python-pip.html), [хранилище](https://docs.amvera.ru/applications/storage.html), [SQLite](https://docs.amvera.ru/databases/sqlite.html).

## Возможности

- Исследования: список, ответственный, срок, описание, этапы «Разработка», «Полевой этап», «Обработка», «Завершено».
- Календарь задач с датами, статусом выполнения, PDF/JPG-вложениями и месячной сводкой.
- Файлы: ТЗ, анкета, гайд и другие вложения до 5 МБ каждый.
- Роли: администратор управляет приложением и учётными записями; исследователь ведёт проекты, материалы и фокус-группы; интервьюер собирает ответы.
- Полевой опрос: устанавливаемый на телефон веб-клиент (PWA), кнопка «Отказ», заполнение без обязательного сбора персональных данных и выгрузка ответов в CSV (UTF-8 с BOM).
- Офлайн-режим: ранее загруженные анкеты и новые ответы/отказы доступны на устройстве без сети и отправляются после восстановления связи.
- Автоматический отчёт прямо в карточке исследования: данные онлайн-опроса и загруженные Excel-анкеты учитываются вместе; графики, описания и таблицы доступны в браузере и в PDF.
- Чат внутри каждого исследования для администраторов и исследователей; сообщения доступны в карточке проекта при подключении к серверу.
- Независимые квоты по вариантам и числовым диапазонам, прогресс на главной странице исследователя и в карточке проекта.
- Анализ связи двух переменных и итоговые описательные выводы в отчёте и PDF.
- Сотрудники в исследовании, персональные составные квоты и ссылка для респондентов без учётной записи.
- Фокус-группы: гайд модератора, запись микрофона с согласия участников, защищённое хранение аудио и локальная расшифровка.
- Отдельный редактор текстовых черновиков анкет и гайдов с боковым ИИ-помощником DeepSeek.
- Аналитическая записка для руководства: генерация по агрегированным результатам исследования и отдельный PDF для скачивания. На её основе можно создать и отредактировать презентацию PPTX.
- Мониторинг Telegram: поиск публичных каналов через Telethon, подтверждение подписки пользователем, посты и доступные комментарии за заданный период с ссылками на источники и обновлением отчёта в реальном времени.

## Мониторинг Telegram

Мониторинг работает только с публичными Telegram-каналами. Пользователь задаёт исследовательский вопрос, регион работы сообществ и подтверждённые каналы, а также период сбора — сколько часов назад включать посты и комментарии (по умолчанию 24 часа, допустимо от 1 до 720 часов). Система читает публичные посты и доступные комментарии за этот период, считает наблюдаемые тренды и тональность, выделяет страхи, потребности, недовольство, инициативы, события и конфликтную риторику. При наличии `DEEPSEEK_API_KEY` или `key.txt` формируется подробный отчёт ИИ с разделением фактов, интерпретаций и гипотез, а также ссылками на материалы.

Администратор и исследователь открывают вкладку «Медиаанализ», вводят вопрос, регион, период и каналы. У каждого материала сохраняются тип (пост или комментарий), канал, текст, ссылка, вовлечённость, дата публикации и дата сбора. Идентификаторы пользователей не используются как доказательство личности; выводы о персонах делает ИИ только по явно названным в тексте людям и обязан прикладывать ссылки. Пока мониторинг включён, он повторяет сбор через выбранный интервал, а открытая карточка обновляет отчёт в реальном времени (примерно раз в 15 секунд); наблюдение продолжается до остановки кнопкой «Пауза». Повторяющиеся публикации отсекаются по адресу, поэтому новые прогоны добавляют только свежие материалы.

Для Telegram задайте на сервере `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` из [my.telegram.org](https://my.telegram.org). Для первой авторизации приложение запросит номер телефона, код Telegram и пароль 2FA при наличии. Сессия сохраняется в `TELEGRAM_SESSION_FILE` (по умолчанию `data/telegram.session`), поэтому на Render нужен постоянный диск. Файл сессии и значения API нельзя добавлять в Git. Поиск показывает публичные каналы до подписки; подписка запускается только после явного нажатия пользователем. Для автоматизации рекомендуется отдельный пользовательский аккаунт.

Новая тема проверяется автоматически в течение примерно 15 секунд, затем через установленный интервал (15–1440 минут). Можно запустить проверку вручную, приостановить или удалить тему вместе с её материалами. URL публикации устраняет повторы; для каждой темы хранятся не более 2000 последних материалов. В интерфейсе видны последние 100; выгрузки JSON (сводка и все сохранённые материалы), CSV (таблица материалов, UTF-8 BOM) и Markdown (текстовый обзор со ссылками) содержат все сохранённые записи. Данные находятся в общей SQLite-базе: для периодического сбора сервер должен работать, а при развёртывании базе нужен постоянный диск и одна реплика. Мониторинг не требует ключа DeepSeek, но подробный отчёт ИИ формируется только при его наличии.

Доступность и полнота зависят от прав пользовательского аккаунта Telegram, доступности публичных каналов и комментариев. Регион используется как поисковый контекст и не доказывает, что каждый автор живёт в нём. Тональность и словарные показатели — предварительная автоматическая оценка. ИИ не должен выдавать выборку публичных каналов за мнение всех жителей региона; существенные выводы необходимо проверять по ссылкам и нескольким независимым материалам.

## Редактор и ИИ-помощник

Только администратор может открыть вкладку «Редактор», выбрать исследование и документ: текстовый черновик анкеты, черновик гайда или гайд уже созданной встречи. Большое поле сохраняет текст на сервере кнопкой «Сохранить»; при попытке уйти с несохранённым текстом появляется предупреждение. Из черновика гайда можно создать встречу, а сохранение гайда существующей встречи сразу обновляет его для модератора. Редактор и ИИ требуют подключения к серверу.

Черновик анкеты **не меняет опубликованную анкету**. Для переноса вопросов в интерактивный опрос разделите их пустой строкой, варианты ответа начинайте с `- ` на отдельной строке и нажмите «Перенести в конструктор». Перед публикацией проверьте типы, обязательность и формулировки в конструкторе; действующие ограничения на изменение анкеты после сбора ответов и настройки квот сохраняются.

Чтобы включить ИИ-помощника, поместите API-ключ DeepSeek в `key.txt` рядом с `server.py` (одной строкой) и перезапустите сервер. Файл исключён из Git; не публикуйте и не пересылайте его. Если файла нет, можно задать ключ через окружение и запустить сервер из того же окна PowerShell:

```powershell
$env:DEEPSEEK_API_KEY = "ваш_новый_ключ"
python server.py
```

Модель `deepseek-flash` используется через `https://api.deepseek.com/chat/completions`. При наличии `key.txt` он имеет приоритет перед `DEEPSEEK_API_KEY`. Ключ не отправляется браузеру. Включённый переключатель «Подсказки при редактировании» автоматически отправляет текущий текст в DeepSeek после паузы в наборе, не чаще одного раза в 15 секунд. При ручном запросе также передаются вопрос и последние реплики беседы; файлы проекта и ответы респондентов не передаются. Не вставляйте в редактор персональные данные и конфиденциальную информацию. Помощник может ошибаться и **не ищет в интернете**. Редактор и запросы доступны только администратору, не более шести запросов в минуту.

## Роли и удаление

Администратор имеет полный доступ, управляет командой и редактором и может безвозвратно удалить карточку вместе с её анкетами, ответами, файлами, отчётами и фокус-группами. Исследователь работает с карточками исследований, их материалами, отчётами и фокус-группами, но не заполняет анкеты и не открывает редактор или список сотрудников. Интервьюер видит только доступные анкеты и может отправлять ответы или фиксировать отказ; файлы, карточки, отчёты, чат и фокус-группы ему недоступны. Удаление требует отдельного подтверждения в карточке исследования.

## Календарь задач

Администратор и исследователь открывают вкладку «Календарь», выбирают дату и создают задачу с названием, описанием и, при необходимости, ссылкой на исследование. После сохранения задачи к ней можно прикрепить PDF или JPG/JPEG до 5 МБ на файл, скачать или удалить вложения. Задачи можно переносить на другие даты, помечать выполненными и удалять. Сводка за показанный месяц содержит число задач, выполненных и просроченных задач и вложенных файлов; содержимое файлов не анализируется. Интервьюеру календарь недоступен. Задачи и вложения хранятся в той же SQLite-базе, что и остальная информация; при удалении исследования связанные задачи остаются в календаре без привязки к проекту. Для Render база должна находиться на постоянном диске (`LAB_DB`), иначе вместе с остальными данными пропадут и задачи календаря.

## Аналитическая записка для ведомства

При создании или изменении исследования заполните отдельные поля «Цель исследования» и «Задачи исследования» (задачи можно записать по одной на строке). Они отображаются в карточке и включаются в оба PDF-отчёта. В карточке администратор или исследователь нажимает «Сформировать с ИИ» и подтверждает отправку агрегированных показателей в DeepSeek. Нужны не менее 10 анкет. Записка включает социологический обзор, направление ответов в текущем срезе (без утверждений о динамике во времени), разбор каждого вопроса в порядке анкеты с разделением фактов и интерпретаций, а также подробные выводы и ограничения; при недостатке данных выводы по отдельному вопросу не делаются. Повторная генерация заменяет сохранённую версию; не более трёх генераций за 10 минут. Изменение цели, задач или статистики помечает прежнюю записку устаревшей; PDF основан на снимке на дату генерации.

В блоке «Презентация по записке» задайте пожелания, от 3 до 20 слайдов, аудиторию, тон, визуальный стиль, плотность, формат и одну из восьми цветовых схем. ИИ в два этапа сначала превращает пожелания в креативный бриф, затем строит драматургию и содержание слайдов. После генерации выберите слайд, нажмите на текстовый блок для редактирования либо перетащите его мышью/касанием, затем нажмите «Сохранить правки» и скачайте PPTX. Презентация и положения её блоков хранятся в SQLite; повторная генерация заменяет их. В DeepSeek передаются только сохранённая аналитическая записка, её обезличенная статистическая основа и введённые пожелания. Лимит — три генерации презентаций за 10 минут на пользователя. При изменении данных или записки презентация помечается устаревшей; перед передачей проверьте её содержание и обновите при необходимости.

Новые слайды используют развёрнутые тезисы и отдельный главный вывод: титульный слайд, содержательные карточки и финальные выводы оформляются ярлычками, мягкими цветными панелями, акцентами и нумерацией. В предпросмотре можно менять текст ярлычка и вывода, положение блоков, размер и цвет шрифта, фон каждого слайда; все правки сохраняются вместе с оформлением и экспортируются в PPTX. Для старых презентаций сохраняется прежний вид, пока вы не сформируете их заново. Если текста много, после экспорта проверьте переносы строк на слайдах.

Для оформления по готовому примеру загрузите в том же блоке PPTX-образец до 5 МБ **перед** генерацией. Приложение извлекает из первых слайдов фон, цвета и шрифты заголовков и основного текста, а также расположение текстовых блоков; выбранные цвета можно затем изменить вручную. Текст, изображения, графика и анимация образца не копируются и не передаются в DeepSeek. В SQLite хранится только извлечённое оформление и имя файла, отдельно для каждого исследования; образец можно заменить или удалить. Загрузка другого образца не изменяет уже созданную презентацию: для применения оформления сформируйте её заново. Поддерживаются образцы с обычными текстовыми блоками и сплошными RGB-заливками; оформление, построенное на изображениях, градиентах или темах без явно заданных цветов и шрифтов, может воспроизводиться частично.

Для новых презентаций краткие содержательные слайды с главным выводом автоматически получают разные компоновки: две колонки или крупный вывод; более длинные материалы остаются в широкой карточке. В редакторе слайда можно переключить компоновку, выбрать из восьми цветовых схем и дополнительно настроить фон и шрифт. Предпросмотр показывает те же панели и расположение текста, что и PPTX. Выбранные темы и компоновки сохраняются вместе с правками после нажатия «Сохранить правки»; старые презентации с сохранённым оформлением продолжают открываться. Не используйте чужие изображения и шаблоны без разрешения: встроенное оформление создано из фигур и цветов, без заимствования графики из галерей.

В DeepSeek передаются название, цель и задачи исследования, общие объёмы, названия всех вопросов, безопасные агрегированные распределения (каждая ненулевая категория не менее пяти анкет, база вопроса не менее 10) и средние по числовым вопросам с базой не менее 10. При малых группах и открытых ответах передаются только названия вопросов, база и указание на отсутствие доступного распределения; тексты ответов, личные коды, имена сотрудников, файлы и расшифровки не отправляются. Не включайте персональные данные в цель, задачи или формулировки вопросов. Модель **не проверяет внешние источники**: перед передачей в ведомство проверьте каждое число и аналитическое предположение; без подтверждённой репрезентативности нельзя обобщать результаты на население. Обычный отчёт и его PDF остаются отдельными документами. Аналитический PDF использует TTF-шрифт с кириллицей, 14 pt, абзацный отступ 1,25 см и выравнивание основного текста по ширине; при наличии Times New Roman он используется первым. На сервере без подходящего системного шрифта укажите путь к `.ttf` в `PDF_TIMES_FONT`.

## Команда исследования и публичная анкета

Сначала создайте учётные записи сотрудников в разделе «Команда».

Администратор в карточке проекта открывает «Добавить сотрудников», затем «Настроить составные квоты». Составная квота состоит из условий по **разным вопросам**: нужный вариант (`single`/`multiple`) и/или числовой диапазон (`number`). Все условия связаны логическим «И». Для «женщины 35+» выберите вариант «Ж» в вопросе о поле и нижнюю границу `35` в вопросе о возрасте. Верхняя граница, если задана, не включается. Квоты показывают прогресс и не блокируют анкету. В персональной квоте учитываются только ответы, отправленные данным сотрудником через полевой опрос; Excel и ответы респондентов по ссылке не относятся к сотруднику. Одна анкета может попадать сразу в несколько составных квот. Удалите персональные квоты перед исключением сотрудника из команды. Назначение команды сейчас служит для планирования и не ограничивает доступ интервьюеров к анкетам.

После настройки анкеты создайте ссылку в карточке проекта и перешлите её респондентам. Для ответа не нужен вход в систему. Ответы по ссылке включаются в общий отчёт и CSV с источником `public`, но не в персональные квоты. Ссылку можно отключить или перевыпустить (старая перестанет работать); уже собранные ответы сохранятся. Доступ по ссылке предоставляется любому, кто её получил: используйте HTTPS, не публикуйте ссылку бесконтрольно и не включайте в вопросы лишние персональные данные. Опрос по ссылке требует подключения к интернету; офлайн-очередь есть только у сотрудников.

## Фокус-группы

### Цифровая фокус-группа по комментариям Telegram

В разделе «Фокус-группы» администратор или исследователь может создать цифровую группу для исследования. Сначала запустите Telegram-мониторинг и соберите как минимум три комментария. При создании выберите мониторинг и число цифровых участников (2–5), загрузите текстовый гайд `.txt`/`.md` до 100 КБ либо вставьте его текст. Приложение сохраняет снимок комментариев выбранного мониторинга: позднейшее удаление мониторинга не удалит источники уже созданной группы.

Модератор задаёт вопросы вручную. При каждом ходе система отбирает релевантные комментарии из снимка базы знаний, отправляет в DeepSeek вопрос, фрагменты комментариев и недавний диалог, затем получает реплики цифровых участников. Участники могут реагировать и возражать друг другу; ссылки на комментарии отображаются под каждой репликой. История сохраняется в исследовании, группу можно завершить. Для работы требуется `DEEPSEEK_API_KEY` (или `key.txt`) и доступ к DeepSeek. Поиск источников использует лексическое ранжирование, без отдельной векторной БД; качество зависит от собранных комментариев. Это **симуляция позиций**, не реальные респонденты и не репрезентативная фокус-группа. Тексты комментариев и гайд передаются в DeepSeek; не используйте персональные данные.

Администратор и исследователь создают встречи, записывают их и исправляют расшифровку. Интервьюеру фокус-группы недоступны.

Во вкладке рабочего пространства «Фокус-группы» выберите исследование, создайте встречу и вставьте текст гайда (пункты с новой строки). Встречи также доступны из карточки проекта. Откройте встречу: во вкладке «Гайд» пункты можно листать кнопками и прокручивать; вкладка «Запись» содержит диктофон и прослушивание, вкладка «Расшифровка» — текст для проверки и исправления. Получите согласие **всех участников**, отметьте его в интерфейсе, затем включите микрофон. Браузер запросит разрешение; нужен HTTPS или `localhost`. После остановки запись загружается на сервер; максимум 24 МБ на встречу. При ошибке загрузки **скачайте локальную копию**, не закрывая вкладку; затем повторите попытку. После сохранения аудио расшифровка запускается автоматически; открытие старой записи без текста тоже запускает её. Готовый текст появляется во вкладке «Расшифровка». Если распознавание завершилось ошибкой, аудио остаётся доступным, а запуск можно повторить кнопкой. Запись и текст доступны администраторам и исследователям. Проверьте и исправьте текст вручную: распознавание не гарантирует точность и не разделяет реплики по говорящим.

Движок `faster-whisper` не входит в базовую установку Render. Для включения расшифровки установите дополнительные зависимости командой `python -m pip install -r requirements-asr.txt` и перезапустите `python server.py`. Используется CPU и модель `small` (русский язык); при первом запуске модель загружается из интернета, требуется свободное место и память. Для полностью автономной работы заранее скачайте модель и укажите путь в `ASR_MODEL`; аудиозаписи **не отправляются** в облачный сервис. Расшифровка продолжительных встреч может занять несколько минут. Если речь не распознана, вместо пустого результата показывается ошибка: проверьте звук и попробуйте снова. Запись хранится в SQLite `data/lab.db`: предусмотрите достаточно места, резервное копирование и контроль доступа. В случае отказа от записи не сохраняйте аудио и транскрипт без согласия участников.

## Квоты, чат и связи

В карточке проекта нажмите «Настроить квоты». Для каждого вопроса с одним или несколькими вариантами укажите план для нужных ответов; пустое поле не создаёт квоту. Для числовых вопросов задайте непересекающиеся диапазоны `[от, до)` и план анкет. План `0` отображает собранное количество, но не блокирует опрос; квоты в целом показывают ход сбора и не останавливают интервью при превышении цели. Для множественного выбора одна анкета может учитываться сразу в нескольких вариантах. Квоты считаются **по каждому вопросу независимо**, по числу отправленных анкет без весов, отказов и неотправленных ответов с телефонов. Редактирование анкеты с настроенными квотами запрещено; удалите настройки перед изменением вопросов, если ответы ещё не собраны.

Чат привязан к исследованию и доступен администраторам и исследователям. При открытой карточке сообщения обновляются приблизительно раз в 12 секунд. Это онлайн-функция: офлайн-отправка сообщений и уведомления вне открытого приложения не поддерживаются. Не отправляйте в чат персональные данные респондентов или пароли.

В блоке «Отчёт и данные» выберите два разных вопроса типа `number` или `single` для анализа связи; `multiple` и свободный текст не поддерживаются. Для двух числовых переменных рассчитывается взвешенный коэффициент Пирсона `r` (от −1 до 1), для двух вопросов с одним вариантом — взвешенный V Крамера (от 0 до 1), для числового вопроса и вопроса с одним вариантом — взвешенное отношение корреляции `η` (от 0 до 1). Используются только анкеты с ответами на оба вопроса; применяются сохранённые веса и групповые коэффициенты отчёта. При менее чем трёх полных парах или отсутствии изменчивости показатель не рассчитывается. V Крамера и `η` не имеют знака направления; ни один из показателей не доказывает причинность или статистическую значимость. Конец отчёта и PDF содержит описательные выводы по первым пяти вопросам, статус квот и выбранную связь, а не автоматическое причинное объяснение данных.

## Импорт Excel и веса

В карточке проекта нажмите «Загрузить ответы Excel». Принимаются заполненные книги `.xlsx` до 5 МБ и 10 000 строк за один импорт; используется первый лист, первая строка содержит названия столбцов. Формат `.xls` не поддерживается. Если у проекта уже есть анкета, каждому вопросу должен соответствовать столбец `q1`, `q2` и т. д. либо столбец с точной формулировкой вопроса. Остальные колонки с ответами не допускаются. Если анкеты ещё нет, она автоматически создастся по заголовкам: числовые колонки станут числовыми вопросами, колонки с небольшим числом вариантов станут вопросами с выбором, остальные будут текстовыми. Проверьте автоматически созданную анкету перед продолжением онлайн-опроса.

| code | weight | q1 | q2 |
| --- | ---: | --- | --- |
| Р-001 | 1.5 | Да | Часто |
| Р-002 | 0.8 | Нет | Редко |

`code` (обезличенный код) и `weight` (вес анкеты) необязательны. Вес по умолчанию 1; допустим положительный вес не больше 1000. Для множественного выбора перечисляйте варианты в ячейке через `;` в точности как в анкете. Ошибка хотя бы в одной строке отменяет весь импорт. Повторная загрузка того же файла добавит ответы повторно.

Онлайн-анкеты сохраняются с весом 1, поле веса из анкеты убрано. В карточке исследования в блоке «Взвешивание отчёта» администратор/исследователь выбирает вопрос с **одним вариантом ответа** и задаёт положительный коэффициент каждому варианту. Коэффициент умножается на сохранённый вес каждой анкеты (в том числе импортированной из Excel или ранее собранной с индивидуальным весом); для пропущенного ответа коэффициент равен 1. Исходные анкеты и CSV остаются неизменными. Выбор «Без группового взвешивания» отменяет коэффициенты. Отчёт и PDF обновляются автоматически. Отчёт показывает число ответивших, сумму весов ответивших на вопрос, взвешенные частоты, графики и проценты от взвешенной базы вопроса; для числовых вопросов также считается взвешенное среднее и строится распределение по восьми равным диапазонам (если все значения одинаковы, показывается один столбец). Описания отмечают наиболее частый вариант либо диапазон и среднее числовых ответов; для свободного текста показаны до 10 наиболее частых точных ответов без смысловой группировки. Пустые ответы в базу вопроса не входят. Для множественного выбора сумма процентов может превышать 100%. Это описательная обработка заданных весов, **не** автоматический расчёт весов по демографическим квотам.

## Телефон и работа без сети

Откройте приложение по HTTPS на телефоне и войдите в свою учётную запись при наличии интернета. Дождитесь загрузки исследований и анкет. Затем установите приложение на главный экран через меню браузера («Добавить на главный экран»/«Установить приложение»). В разделе «Полевой опрос» заполняйте анкеты или нажимайте «Отказ»; отказ учитывается отдельно от анкет в карточке исследования и PDF. Данные сначала сохраняются в IndexedDB на **этом устройстве**; счётчик в верхней части экрана показывает неотправленные записи. При возвращении сети они отправляются автоматически, когда приложение открыто; браузеры с поддержкой Background Sync могут отправить их и в фоне. Если автоматическая отправка задерживается, откройте приложение и нажмите «Отправить». Повторные попытки не создают дубликатов на сервере.

Не удаляйте данные сайта, не используйте режим инкогнито и не удаляйте приложение до появления «Все данные отправлены». Очередь привязана к учётной записи, которой собирались данные: после выхода войдите под **той же** учётной записью для синхронизации. При ошибке проверки ответа запись остаётся на телефоне, пока не будет устранена причина; не рассчитывайте на отправку в фоне на всех моделях телефона. До синхронизации записи не входят в статистику сервера. Офлайн-данные хранятся локально в браузере без дополнительного шифрования: используйте блокировку экрана, не записывайте персональные данные респондентов без необходимости и не работайте на чужом телефоне. Для установки и офлайн-режима нужен HTTPS (исключение: `localhost` на самом устройстве); адрес вида `http://192.168.x.x:8000` без HTTPS не поддерживает сервис-воркер.

Для PDF нужен установленный системный шрифт с кириллицей (Windows Arial, Linux DejaVu Sans). Если сервер его не обнаружил, укажите путь к `.ttf` в переменной окружения `PDF_FONT`.

Анкету можно составить в интерфейсе или импортировать из JSON. Пример:

```json
{
  "questions": [
    {"label": "Как часто вы пользуетесь транспортом?", "type": "single", "required": true, "options": ["Ежедневно", "Реже", "Никогда"]},
    {"label": "Что стоит улучшить?", "type": "textarea", "required": false}
  ]
}
```

Типы: `text`, `textarea`, `number`, `single`, `multiple`. PDF/DOCX можно прикрепить как файл проекта, но для заполнения анкеты в браузере вопросы нужно создать в редакторе или импортировать из JSON. После первого собранного ответа редактирование вопросов заблокировано, чтобы колонки в CSV не изменились.
